# 故障判断与恢复

`GET /api/runs/{run_id}/trace` 返回当前owner范围内的阶段、实际模型/工具调用、来源、错误码、审批、产物和业务事实。已配置工具数与本run执行数分别呈现；调用参数不进入诊断响应。`usage` 未由模型提供时保持未知。

故障处理按事实分类：等待用户输入的run保留原checkpoint；已提交operation只返回原提交结果；`processing`先核查租约；`outcome_unknown`必须按外部关联号对账；存在checkpoint才允许从原版本恢复；没有checkpoint且没有业务效果时以失败结束。取消只停止后续调度，不能撤销已提交事实。数据库不可用时不创建新的业务写入。Docker/MCP故障不触发宿主Shell或数据源静默回退。

断线先用run_id读取持久事件。服务重启后不要重复点批准或重复调用写工具；先查订单与operation。报告容器错误时只恢复容器，不影响本地只读查询。真实ERP请求超时按P08对账契约处理；没有真实ERP环境时不做写入演练。
