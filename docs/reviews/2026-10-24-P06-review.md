## P06 发现

### P06-R01 [P1] Linux 沙箱上传失败，远程 CI 未通过

位置：`backend/app/sandbox/runner.py:25–42`，特别是33–34行。

上传代码直接对 Docker SDK 返回对象调用 sendall/shutdown，假定它是 socket。当前 Windows 能运行，但 Linux 返回 SocketIO，无 sendall。已通过 GitHub 连接读取 [CI run 40105755949](https://github.com/newerwell/technologyagent/actions/runs/40105755949) 的 job `120906984100`：b905f0d，Failure；镜像构建成功，集成测试 **5 failed、144 passed**，错误为 `AttributeError: 'SocketIO' object has no attribute 'sendall'`，位置 runner.py:33。前端和契约检查成功不改变此结果。

应适配 Docker 不同传输返回对象的受支持读写接口，处理完整写入、关闭和传输异常，不能仅替换成另一平台私有属性。保留 Windows 实测，并在干净 Linux CI 真容器中验证上传、执行、图表、输出与回收；修复 CI 后才能关闭交付项。

### P06-R02 [P1] 报告内容可错误，但产物与运行仍“评审通过”

位置：`backend/app/agent/tools/analysis.py:83–98`；`services/artifacts.py:35–63`；`agent/graph.py` 的候选正文评审路径。

运行时仅注册 analysis_execute，任意代码输出经格式检查就直接 register、发 artifact_ready；固定 `charts.py/reports.py` 仅被样例脚本及测试调用。实际业务路径没有使用这些模块来保证采购文件结构、数值和范围。评审检查最后一句正文，不读取文件内容。

本轮受控内存整链运行真实 GraphExecutor→AnalysisToolRegistry→ArtifactService，模型、沙箱与落盘边界替换为可控组件：成功报价输入 Q01/Q02 单价1200/1100分，请求55件，CSV却将两家总额都写成9999分，正文仅“报告已生成。”。实际 run completed，NUMERIC_MATCH/SCOPE_MATCH/SOURCE_EXISTS/PLAN_EVIDENCE/SEMANTIC_COMPLETE全通过，文件ready且发事件；正确金额应为66000/60500分。此为确定性故障注入，不冒充真实模型生成行为。

修复：把采购图表/报告接入受控 ChartSpec/AnalysisResult 渲染与事实核对，按请求检查必需文件，再发布正式产物。通用分析代码仍可保留，但不能凭格式正确或一句说明就把错误业务文件标为已核验。验收须从查询、Agent调用一直到下载后解析，包含错误金额、仓库、失效报价和遗漏输出。

### P06-R03 [P1] 15秒工具时限与30秒容器冲突，调用超时不会停止容器

位置：`agent/graph.py:239–241`及GraphExecutor默认tool_timeout=15；`agent/tools/analysis.py:81–87`；`sandbox/runner.py:74–75,109–147`。

analysis_execute 默认 SandboxJob30秒，但通用工具入口在15秒取消等待；Docker execute 只是 to_thread，取消协程不取消后台线程或容器，最终结果也回不到登记步骤。主审真实 Docker 探针用2秒正常作业、1秒调用端wait_for：调用已Timeout，仍有 **1个running容器**；后台完成后才回收为0。该探针验证取消语义，实际15–30秒的同类问题由生产配置确定；不是声称本轮跑了30秒恶意负载。

此外上传和输出收集不在job计时区间内；收集使用同步exec_run，没有统一剩余期限。应让任务全生命周期受run预算和任务期限控制，给不同effect明确工具时限，取消/超时主动终止并等待回收；登记前再次检查run状态。验收包括合法20秒作业、整体30秒上限、执行中取消、收集失败/超时，不能仅直接调用runner绕过Graph验证。

### P06-R04 [P1] 可选 Docker 探测阻断普通库存查询

位置：`agent/tools/analysis.py:108–111`；`sandbox/runner.py:59–71`；`agent/graph.py` 的 registry_factory 超时路径。

工厂在返回任何只读工具前，无独立短时限地等待Docker available；Docker客户端超时35秒，而整个registry准备只有15秒。主审实际 GraphExecutor、真实 AnalysisRegistryFactory 的受控慢依赖探针，将时限缩放为0.03秒、Docker探测0.2秒后返回不可用，结果 failed/TOOL_TIMEOUT，模型调用0、只读工具调用0。不是Docker不可用即隐藏分析，普通查询也被拦住，与A06相反。

修复：隔离可选能力探测的期限/缓存/失败结果，基础只读registry不依赖Docker响应；Docker慢、断连、缺镜像都不影响普通查询，分析工具返回明确不可用。测试应经过GraphExecutor，不能只让fake available立即返回False。

### P06-R05 [P2] 同会话追问后，旧文件卡片消失且无法恢复

位置：`frontend/src/hooks/useChat.ts:110–119,248`、`lib/event-reducer.ts:102,187–188`、`backend/app/services/runs.py:743–759`。

发送下一轮时emptyChatState清空artifacts；重开会话只取latest_run事件，历史消息没有文件引用，旧run事件还会被reducer拒绝。实际执行现有TypeScript reducer：run1卡片1→追问清空0→重开run2仍0，旧消息保留但无下载入口。文件仍在服务端，不代表用户能从历史找回。

修复：持久关联会话/消息/run/产物并提供owner-scoped历史查询，UI分run恢复旧文件，不能把旧事件硬塞到当前run的seq。验收“生成→追问→刷新→重选会话”，旧下载/预览保持可用；浏览器要真实点击下载并核对内容。

### P06-R06 [P2] 正式产物来源变成无法追溯的临时ID

位置：`agent/tools/analysis.py:43–49,64–72,89–95`；`sandbox/reports.py:29–77`。

缓存只保留工具data字节，产物引用仅为tool_result:ds_uuid；该ID只存在当前registry内存，无持久映射/查询，丢失原工具call_id、记录来源及观察时间。上述整链探针产物事件没有Q01/Q02和时间；浏览器夹具手工填quote:Q01，掩盖了实际行为。

主审另用唯一来源ID调用正式build_report_spec：JSON保留source_refs，Markdown/HTML/CSV均没有输出该ID。当前样例summary恰好手写Q01/Q02，不能代表通用渲染器保留来源。

修复：沿授权数据→转换→文件→事件保留可持久定位的工具/记录/时间和范围，在四格式报告中稳定输出来源；临时dataset ID仅用于运行内输入。run关闭和服务重启后也须可核对，不能仅断言source_refs列表非空。

### P06-R07 [P2] CSV公式保护遗漏表头和元信息

位置：`sandbox/reports.py:40–53`。

只转义明细中非numeric_columns的字符串，表头、scope、summary、recommendations、missing_fields直接写入。主审真实函数回读：表头`=1+1`、scope`=1+1`、结论`=2+2`、建议`=3+3`均原样保留，而明细字符串被加前缀。numeric_columns也未验证对应值真是数值，可错误跳过字符串保护。

修复：所有字符串单元格走同一编码/转义入口，数值列验证类型而非按索引盲信；保留合法数字。测表头、明细、范围、时间、结论、建议、缺项和带空白前缀，不能只验证一个明细公式。
