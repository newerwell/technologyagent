# P09：综合验收、异常恢复与运行交付

状态：待实施。依赖：P08。目标：获得可重复演示和可诊断的本地完整版本，明确真实模型与ERP验证范围。

## 任务

- [ ] **P09-T01 可观测性。** `services/tracing.py` 按request/thread/run/call关联阶段、委派、工具、审批、产物；记录duration、次数、usage（若提供）、来源和错误；敏感配置脱敏；提供按run查询摘要，不以已配置工具数冒充执行次数。
- [ ] **P09-T02 故障与限额。** `services/recovery.py` 处理模型超时、MCP断开、DB失败、Docker故障、服务重启；失败工具明确可否重试。核对cancel/断流/processing/outcome_unknown一致性；DB无法持久化时不提交新业务写入。
- [ ] **P09-T03 端到端场景。** 建立FINAL-ACCEPTANCE案例，脚本可重置独立测试库并隔离产物；每次报告fixtures版本、模型与参数、次数、成功率、实际工具轨迹、数据源、耗时。修复失败后只重跑受影响案例及必要回归。
- [ ] **P09-T04 浏览器与视觉验收。** 桌面1440×900和手机390×844验证消息、表格、审批、报告、错误、历史；核心按钮可操作，表格允许内部横向滚动，主体无横向溢出。保存关键截图及人工操作记录。
- [ ] **P09-T05 运行交付。** 完成README、.env.example、start/stop、健康检查、日志位置、数据库/产物备份恢复、示例提示词、故障处理；从全新目录按锁文件安装并跑通，不依赖开发者临时路径；清理本次无用临时产物。
- [ ] **P09-T06 总验收与边界说明。** 填写FINAL-ACCEPTANCE全部实际状态，标记已实施/离线/真实模型/浏览器/真实ERP；明确剩余缺口。若要部署到非localhost，先完成真实登录会话、owner绑定、凭证管理、HTTPS与访问限制的部署规格和验证，本阶段默认只交付本机版本。

## 验收

| ID | 操作 | 通过条件 |
|---|---|---|
| P09-A01 | 全新环境按文档启动，运行完整演示 | 前后端、DB、MCP、模型、Docker各自状态可见，完成报告与订单闭环 |
