## 失败与修复记录

- **PyMongo async 事务 API**：首次实现把 `session.start_transaction()` 直接用于 `async with`，`/ready` 报 `TypeError: transaction probe failed`。实际 API 需要先 `await` 得到异步上下文管理器；修复后事务回滚探针与集成测试通过。
- **DB 关闭时会话创建返回 500**：首次浏览器降级验证中 `POST /api/session/local` 返回 `internal server error`。改为捕获存储异常并返回 `DEPENDENCY_UNAVAILABLE/503`，重跑会话测试 11 passed。
- **前端测试运行时兼容**：最初使用 Vitest 5 + TypeScript 7 + Vite 8 时，`.tsx` 被 Rolldown 以“Unexpected JSX expression”拒绝；改为锁定 Vitest 4.1.12、Vite 7.3.7、TypeScript 5.9.3、@vitejs/plugin-react 5.2.0 后 2 passed。
- **页面状态样式**：首次浏览器截图发现“就绪”沿用错误 badge 颜色、长 model 说明溢出卡片；修正状态映射与 `dd`/badge 布局后重新构建并截图。
- **Mongo 重启后的测试时序**：执行 `docker compose stop/up` 后立即跑测试，容器尚未完成 `rs.initiate`，测试按设计报“不是 replica set”；运行 `init_db` 等待 primary 后 11 passed。这不是产品通过；说明测试前必须先初始化 replica set。
- **启动脚本重复实例**：A01 再验证时增强为“应用已运行时仍校验 MongoDB”，避免数据库被单独停止后重复 `start.ps1` 无法自愈；PID 仍不重复。
- **GitHub Actions 首轮失败**：`docker run -p 27027:27027` 没有让容器监听 27027（mongod 默认 27017），导致 `init_db` 等待 primary 超时（run 39950310945 failure）。改为 `docker compose up -d mongodb` + health 等待后，run 39953759929 全步骤 success。失败记录保留，不把首轮失败当作已通过。
