## 实现范围

- 服务端草稿准备、缺字段补充、字段编辑与版本控制；金额来自有效报价快照，按服务端事实计算。
- MongoDB 持久检查点；订单工作流将补充、审批和提交分节点，resume 校验 owner、run、interrupt、版本与决定。
- `MutationService` 在 Mongo 事务内原子更新订单、库存 inbound/version、审批消费及幂等 operation；订单只增 inbound，不增 on_hand。
- 审批卡、补充表单、订单查询和 operation 对账；MCP 原9项只读工具不变，另有4项受控订单工具，未批准创建请求拒绝且不产生 operation。
- 拒绝工作流写入明确结束说明；相同 part/quote 行合并后补货预览只接收唯一 part ID。

边界证据：

- 缺仓库时仅返回 `missing_fields=[warehouse_id]`，不创建草稿；P001/W01/Q01 55 件为 66000 分，改为60件后版本2为72000分；旧版本 patch 返回409。
- 同 part/quote 重复行会合并后再算价；零数量、小数数量、过期报价、停用供应商和未知零件不能生成有效批准草稿。
- 55件订单单测从 seed 的2单增至3单，订单66000分；I001 的 `(on_hand,inbound,projected)` 从 `(20,10,30)` 变成 `(20,65,80)`，在途增加55、现货仍20。
- 同 key 重放和并发请求返回同一订单；同 key 不同 payload 为409；库存版本或报价字段改变使旧批准失效；未批准请求返回403且 operation 数不变。
- `after_claim` 与事务内 `after_order_write` 故障可恢复/回滚；确认未提交时订单数、审批和库存不变，租约失效后可重试；commit 后丢响应通过原 operation/order 读回并 reconcile 为 succeeded。
- reject 保留 rejected 草稿、不创建订单且 run 正常结束；跨 owner resume/审批返回404；过期 interrupt 返回409。
- Mongo saver 关闭并重开后，从同一 thread/run 读取 waiting_input 和 interrupt，再补充、编辑、批准；不会提前创建订单。

最终全量 offline 首轮曾发现两处失败并保留对应断言：拒绝分支缺少明确结束摘要；重复行传入重复 part ID 导致补货预览校验失败。分别修复后，单项回归各1 passed，最终 offline 为9/9通过。
