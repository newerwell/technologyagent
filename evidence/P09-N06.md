## 修改

### 1. 源码/批次归属（新增 `scripts/acceptance_provenance.py`）

- `collect_acceptance_provenance(repository_root)` 记录 checkout 绝对路径、source SHA、分支/游离状态、开始时间、产品脏状态与产品变更路径、docs 单独路径；Git 不可用时 `known=False` 且不猜 SHA。
- 产品范围覆盖 `backend/`、`mcp_server/`、`frontend/src/`、`tests/`、`scripts/`、`fixtures/`、`.github/`、锁文件、启动与 compose 配置；未跟踪源码同样算脏。`.env*/storage/data/.runtime/node_modules` 等不读取、不哈希。
- `finalize_acceptance_provenance` 记录结束 SHA、结束脏状态、`source_drift` 与 `drift_paths`；不修改原报告结论。
- 修正 git 输出解析：保留 porcelain 的状态列前导空格，避免把 `backend/app/main.py` 解析成 `ackend/app/main.py`。

### 2. 报告注入（`scripts/run_acceptance.py`）

- 已存在的报告路径直接拒绝（exit 3），新批次不覆盖旧报告。
- 批次号取 `P09_EVIDENCE_BATCH`，否则时间戳+随机；导出 `P09_BATCH_ID` 供 live attempt 使用。
- 运行前 collect、运行后 finalize，再**只追加** `batch_id`、`provenance`、`acceptance_exit_code`；不重写 `checks`、`ok`、`not_run`，也不改退出码。ERP not_run 分支同样注入。

### 3. live attempt（`tests/live/test_final_scenarios.py`）

- `_record_attempt` 增加 `source_sha` 参数，attempt 记录 `batch_id`/`source_sha`；summary 增加同字段，并断言 13 条记录一致。

### 4. F04 失败前数据库事实（`tests/live/test_order_workflow.py`）

- `before` 计算后、任何工作流请求前即写入 `trace["database_before"]`。
- 取得 run/draft/order ID 后立即写入 trace；新增 `_capture_database_state`、`_capture_order_links`、`_run_with_trace`。
- `finally` 始终保存 `database_after`（订单数、order_create operation 数、已消费审批数、I001 库存，以及按 `order_id` 唯一关联的 order/operation/approval）；DB 读取异常写 `database_after_error`，不覆盖原始失败；最后重新抛出原异常。
- 新增 `tests/unit/test_live_order_trace_capture.py`：本地替身写入订单后抛“说明核验失败”，断言 before/after 均在 trace、原失败保留；DB 读取失败不替换原始错误。
