# P09 R5：远程只读查询统一入口

日期：2026-11-08。范围仅为 `P09-remaining-after-R4-review.md` 的 R5；不开始 R6，不创建 `phase-p09`。

## 实施内容

- 新增 `backend/app/integrations/provider_queries.py`，API 与 MCP 共用远程只读入口。映射后用既有 `Part`、`Supplier`、`InventoryView`、`PurchaseOrder` DTO 校验，不填补必需字段；缺字段和 DTO 不合法返回 `REMOTE_DATA_INVALID`，远端不可用/时限耗尽返回 503。
- Part 的来源单位与布尔启用状态、Inventory 的库存/目标/版本整数、PurchaseOrder及明细必需字段均有独立校验；订单行映射内部的`missing_fields`元数据不进入业务DTO。
- 分页读取会从第一页收集到末页，再返回请求页。逐页校验 `page/page_size/pages/total`、精确记录数、跨页唯一实体ID和稳定 total/pages。最大上限采用保守失败门槛：需要100页或达到10000条时返回不完整错误。每次 HTTP 请求接收剩余查询时间；MCP 外层 run deadline继续覆盖整次工具调用。
- API的零件、供应商、库存/预警/汇总、订单列表/详情接入该服务；MCP业务分发复用同一服务。未映射的远程报价、补货与所有远程写能力继续拒绝，不以Mongo本地结果标成 `remote_erp`。
- 更新 integrations/ERP/API/MCP 模块说明和字段映射文档，记录本地 HTTP 模拟器与真实ERP的边界。

## 反例与验证

- RED：实现前新增定向测试无法导入 `backend.app.integrations.provider_queries`，确认共享查询入口缺失。首次 `uv run` 因用户目录 uv cache ACL 拒绝而未运行测试；将 `UV_CACHE_DIR` 指向仓库 `.runtime/uv-cache` 后开始测试，关闭pytest cache plugin以避开仓库 cache ACL。权限问题不计作产品失败。
- 本地模拟器为持续运行的 loopback HTTP server，不是真实ERP。API和MCP以同一参数查询第二页，均返回同一份严格映射的 S02 供应商记录；服务端为每次调用请求第一页和第二页。
- 模拟器删除必需的 Supplier.status 时，API返回 502 `REMOTE_DATA_INVALID`，并未从本地Mongo取数据。模拟器只返回一页但声明两页、同一实体跨页重复、total/页数矛盾、响应页码错、分页元数据缺失、请求越界、达到页数边界、剩余时限耗尽均被定向拒绝。
- Part、Inventory、Order DTO均有缺字段/类型回归；库存派生值按服务端整数事实计算。本地HTTP模拟器的实际库存摘要保持I001事实：on_hand=20、inbound=10、shortage=55。

  tests/unit/test_provider_queries.py tests/unit/test_p08_erp_adapter.py `
  tests/integration/test_provider_contract.py tests/integration/test_provider_switching.py `
