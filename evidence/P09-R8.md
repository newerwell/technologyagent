## 2026-11-08 R8 端口传递补修

### 反例与实现

在隔离 browser 库、默认 API/前端/MCP `8030/3030/9030` 下先跑 desktop 用例。报告已通过页面实际生成并下载；旧用例随后停止默认服务，再由 `restartEnv` 硬编码的 `8031/3031/9031` 启动。浏览器仍留在 `http://127.0.0.1:3030`，于 `page.reload` 实际失败 `net::ERR_CONNECTION_REFUSED`，Playwright `1 failed`、命令退出码1。失败点在批准前，未新增订单或写 operation；已生成报告及运行轨迹保留。

修复后，`frontend/src/lib/p09-runtime-config.cjs` 是 Playwright config 与根目录 E2E 共用的解析器：默认端口按 `start.ps1` 的 `8030/3030/9030`，显式端口原样传给重启子进程；Playwright baseURL从显式 `P09_BROWSER_BASE_URL` 或同一 `FRONTEND_PORT` 派生，显式URL端口不一致即失败。E2E reset前验证Compose项目、隔离 `ta-rs` URI、固定 browser test库、四项 `local_seed`、空 snapshot及 `fake/RUN_LIVE_MODEL=0`。本轮额外修正E2E CommonJS装载：共享runtime helper使用 `.cjs` 与 `.d.cts`，避免Node将前端ESM TypeScript直接作为CommonJS导入。
